# DEPLOYMENT

## Локальный запуск

```bash
npm install
npm run build
npm start        # http://localhost:3000
```

## Требования

- Node.js ≥ 18 (рекомендуется 20+)
- PostgreSQL **не обязателен** для MVP (in-memory комнаты);
  соединение БД используется только health-проверкой и пригодится
  в v1.1 для персистентности комнат.
- Переменные окружения: `DATABASE_URL` (опционально для MVP),
  публичных ключей не требуется.

## Хостинг

Подойдёт любой хостинг Node.js-приложений (VPS, Render, Railway, Fly.io):

1. Загрузить репозиторий, `npm ci`, `npm run build`, `npm start`.
2. Направить домен на порт приложения (обычно 3000).
3. Обязательно HTTPS (SSE и EventSource работают и по HTTP,
   но PWA/service worker — только по HTTPS или localhost).

## Ограничения платформы

- Комнаты живут в памяти одного процесса. Не запускать несколько
  инстансов за балансировщиком без shared state (в v1.1 — PostgreSQL
  + fan-out), иначе две копии сервера не увидят друг друга.
- Для прод-моста: прокси должен поддерживать long-lived соединения
  (SSE): `proxy_read_timeout` ≥ 60 c, без буферизации ответа.
- Health-check: `GET /api/health`.

## Плейбук инцидентов

| Симптом | Причина | Действие |
|---|---|---|
| Клиент «не в сети», пуш не идёт | SSE оборван прокси | Клиент сам переходит на поллинг; проверить заголовки прокси |
| Комнаты пропали | Рестарт процесса | Ожидаемо для MVP; пересоздать комнату |
| 429 от API | Слишком частые действия | Лимит 40 req/2 с на token (защита от спам-кликов) |
